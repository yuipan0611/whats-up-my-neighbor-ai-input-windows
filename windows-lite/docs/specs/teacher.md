# 老師（TC）

目標：老師永遠只置頂一筆，不會在同學區出現第二條，也能正常更換或移除。不改線上協定。

**TC-01 把既有聯絡人設為老師**
- Given IP `T` 已是學生聯絡人或存在 `ip:T` 對話
- When 使用者選「設為老師」（或「＋ 加入老師」輸入 `T`）
- Then 原本那筆升級為老師並置頂；`ip:T` 歷史依 CT-02 合併；同學區不再有 `T`
- And 歷史、草稿、未讀全部保留

**TC-02 同時只有一位老師**
- Given 已有老師 `T1`
- When 把 `T2` 設為老師並確認「將取代目前的老師」
- Then `T2` 置頂，`T1` 降為學生聯絡人（仍在同學區、歷史保留），不會變成「已移除」

**TC-03 名單老師設定只有一個來源**
- When 設為／取消老師
- Then SQLite `RosterEntry.isTeacher` 為唯一權威，在一個資料庫交易內選定且至多一位；Core 回傳權威老師 IP（無老師為 null）。`Settings.TeacherIp` 僅為 B1-b 投影，在操作後及啟動時由 SQLite 校正，投影寫入失敗可重試，不回滾已提交的老師選擇；不宣稱 SQLite／JSON 跨檔原子提交

**TC-04 取消老師**
- Given 老師 `T`
- When 選「取消老師身分」
- Then `T` 回到同學區成為一般聯絡人；「＋ 加入老師」重新出現

**TC-05 移除老師**
- Given 老師 `T`
- When 依 CT-13 移除
- Then `T` 只出現在封存區，不會掉進同學區；「＋ 加入老師」重新出現

**TC-06 升級舊資料**
- Given 舊版資料庫有多筆 `isTeacher=1`，或老師 IP 同時有 `ip:` 對話，或刪除過的老師
- When 升級到新版並啟動
- Then 舊資料沒有設定時間，不能推斷最近設定者；由啟動 adapter 提供 legacy Settings.TeacherIp（Core option），優先採現有老師中 IP 相符者，否則依 roster id ordinal 選一位。之後有唯一索引保證只保留一位老師，其餘降為學生；`ip:` 對話依 CT-02 合併；若草稿／訊息衝突則保留兩份並記固定診斷，待使用者處理，不讓整個資料庫無法升級、不刪任何訊息。舊刪除快照無 endpoint 不猜測；保留封存
- And 遷移前自動備份資料庫（沿用現行升級備份）

**TC-07 CSV 名單種子**
- Given 空名單首次啟動，`classroom-roster.csv` 標示多位老師
- Then 以 CSV 原始行序（先排除本機）只採第一位為老師，其餘當學生並記錄診斷；不破壞 TC-02；一般 CSV 匯入也須遵守至多一位。既有老師未被明確取代時保留，不因匯入悄悄變更

## S0 Core／WPF 邊界

Core 提供設為老師、取消老師、權威 IP、原子單一化與保存資料的 API；取代前確認／按鈕可見性／JSON 投影只由 B1-b 驗證。自動恢復已移除老師時先成為學生，不自動恢復教師權限。

設為老師是使用者明確操作；即使原本 source=csv，也會轉為 source=manual。

## D-33：本機老師電腦與名單老師分開

TC-03 的 SQLite 權威與 Settings.TeacherIp 只代表「我要傳給誰」，不代表「這台電腦是不是老師」。本機課堂反應角色由 ThisDeviceIsTeacher／ThisDeviceTeacherExplicitChoice 管理，啟動時在投影覆寫前依 RX-07 遷移。固定老師 IP 192.168.24.240 每次啟動自動視為老師，除非舊設定檔明確記錄為非老師（D-37 起設定頁已無勾選入口）；名單沒有自己或更換／取消老師聯絡人均不改本機角色。這個顯示角色不是署名、分享或撤下授權。
