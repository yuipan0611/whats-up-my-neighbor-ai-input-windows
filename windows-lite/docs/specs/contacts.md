# 聯絡人（CT）

決策：D-27（陌生來訊自動成為聯絡人）、D-25（本機備註）。不改線上協定。

## 自動加入與合併

**CT-01 陌生來訊自動成為聯絡人**
- Given B 的名單裡沒有 IP `A`
- When A 傳來的第一則訊息在 B 端成功存入
- Then B 的名單新增一筆學生聯絡人（`isTeacher=0`、`source='auto'`），顯示名稱為 A 的 IP
- And 該訊息屬於這筆聯絡人的對話（`roster:<id>`），清單上沒有另一條「名單外・A」

**CT-02 既有名單外歷史一併合併**
- Given B 端已存在 `ip:A` 對話（例如升級前留下），內含訊息、未讀、草稿、附件與待送
- When CT-01 的自動加入發生，或使用者手動新增 IP `A`
- Then 原 `ip:A` 的訊息、未讀數、草稿、附件、回條佇列、送出嘗試與待送（`ClassroomOutbox.principal`）全部改歸新聯絡人
- And 清單只剩一條 A 的對話，順序與內容不變

**CT-03 自動加入不給任何身分或權限**
- Given CT-01 自動加入了 A
- Then A 不會成為老師、不會被置頂、不會取得課堂檔案的老師節點身分
- And 通知仍以聯絡人名稱顯示；名稱只是本機標示，不代表身分驗證

**CT-04 重複與並行來訊不會建多筆**
- Given A 同時或連續送來多則訊息（含重送同一 messageId）
- When B 端並行處理
- Then 只建立一筆聯絡人；重複 messageId 仍回 duplicate，不重複建列

**CT-05 自動加入失敗不影響收訊**
- Given 自動加入因名單限制或儲存錯誤失敗
- When 收到訊息
- Then 訊息仍照現行規則存入 `ip:A` 並可回覆，不會因為建聯絡人失敗而遺失訊息；失敗以診斷代碼記錄

**CT-06 名單外上限改套在自動加入**
- Given 自動加入的聯絡人已達上限（沿用現行 200 來源）
- When 新 IP 來訊
- Then 依現行 `offroster-limit` 規則拒收，並提示「聯絡人已達上限」

**CT-07 已移除的聯絡人再次來訊**
- Given 使用者先前移除了 A（A 在封存區）
- When A 再次來訊
- Then A 回到一般清單成為聯絡人，沿用原本的備註與歷史，不再產生新的「名單外」列

## 新增、移除、備註

**CT-10 新增聯絡人一步完成** 【WPF】
- Given 使用者點「＋ 新增對象」
- When 填 IP（必填）與備註（選填）並確認
- Then 名單出現該聯絡人並直接開啟對話；未填備註時顯示 IP；對方離線也可新增

**CT-11 新增重複 IP 時引導到既有聯絡人** 【WPF】
- Given IP `A` 已是聯絡人
- When 再次新增 `A`
- Then 不建新列；顯示「已在名單中」並提供「開啟對話」

**CT-12 聯絡人操作集中在一個選單** 【WPF】
- Given 名單中任一聯絡人（含老師）
- When 右鍵或對話標題的 ⋯
- Then 都看得到：編輯備註、編輯 IP、設為／取消老師、移除聯絡人；兩個入口內容一致

**CT-13 移除聯絡人保留歷史、不是封鎖**
- Given 聯絡人 A
- When 選「移除聯絡人」並在確認視窗看到「只從這台電腦的名單移除，歷史會保留在封存區，不會封鎖對方」後確認
- Then A 從一般清單消失、出現在封存區（唯讀，可查看）；取消則不變

**CT-14 編輯備註只影響本機**
- Given 聯絡人 A
- When 編輯備註
- Then 清單、對話標題與通知立即改用新備註；設定視窗明示「只在這台電腦顯示」；對方畫面不變

**CT-15 編輯 IP 時歷史跟著聯絡人**
- Given 聯絡人 A 的 IP 由 `x` 改為 `y`
- Then 歷史與草稿留在同一筆聯絡人；`x` 之後若再來訊，依 CT-01 視為新的陌生來訊（現行 CM-10 已知限制）
