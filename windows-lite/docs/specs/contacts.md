# 聯絡人（CT）

決策：D-27（陌生來訊自動成為聯絡人）、D-25（本機備註）。不改線上協定。

## 自動加入與合併

**CT-01 陌生來訊自動成為聯絡人**
- Given B 的名單裡沒有 IP `A`
- When A 傳來的第一則訊息在 B 端成功存入
- Then B 的名單新增一筆學生聯絡人（`isTeacher=0`、`source='auto'`），顯示名稱為 A 的 IP
- And 該訊息屬於這筆聯絡人的對話（`roster:<id>`），清單上沒有另一條「名單外・A」

**CT-02 既有名單外歷史一併合併**
- Given B 端已存在 `ip:A` 對話（例如升級前留下），內含訊息、未讀、草稿、附件與待送
- When CT-01 的自動加入發生，或使用者手動新增 IP `A`
- Then 原 `ip:A` 的訊息、未讀數、草稿、附件、回條佇列、送出嘗試與待送（`ClassroomOutbox.principal`）全部改歸新聯絡人
- And 清單只剩一條 A 的對話，原訊息 localSeq／createdUtc、內容與未讀保留；同內容同 id 去重，合併已讀／對方儲存證據與未送回條，不把已讀改回未讀。雙方不同非空草稿、不同內容／交付路徑證據同 id、附件傳輸狀態或活動傳送衝突時，拒絕手動合併；自動加入以 CT-05 回退，不覆寫、不默丟資料

**CT-03 自動加入不給任何身分或權限**
- Given CT-01 自動加入了 A
- Then A 不會成為老師、不會被置頂、不會取得課堂檔案的老師節點身分
- And 通知仍以聯絡人名稱顯示；名稱只是本機標示，不代表身分驗證

**CT-04 重複與並行來訊不會建多筆**
- Given A 同時或連續送來多則訊息（含重送同一 messageId）
- When B 端並行處理
- Then 只建立一筆聯絡人；重複 messageId 仍回 duplicate，不重複建列

**CT-05 自動加入失敗不影響收訊**
- Given 自動加入發生可恢復的局部錯誤（不包含 CT-06 容量耗盡或資料庫本身無法寫入）
- When 收到訊息
- Then 訊息仍照現行規則存入 `ip:A` 並可回覆，不會因為建聯絡人局部失敗而遺失訊息；局部修改以 savepoint 回滾，失敗以不含 IP／內容的診斷代碼記錄。資料庫本身無法提交時不回 stored ACK，原傳送端仍可重試

**CT-06 名單外上限改套在自動加入**
- Given 自動加入的聯絡人已達上限（沿用現行 200 來源）
- When 新 IP 來訊
- Then 依現行 `offroster-limit`／rate_limited 規則拒收，UI 可據此提示「聯絡人已達上限」；Core 不改 frozen wire 錯誤碼。自動加入後仍套用每來源／總訊息／byte 上限，不得靠 source=auto 繞過；手動名單不受自動來源名額限制

**CT-07 已移除的聯絡人再次來訊**
- Given 使用者先前移除了 A（A 在封存區）
- When A 再次來訊
- Then A 回到一般清單成為聯絡人，沿用原本 id、備註與歷史，不再產生新的「名單外」列；不恢復老師旗標、peer 綁定或任何權限。新版移除快照保存 endpoint 及必要本機欄位；舊版移除紀錄缺 endpoint，不能猜 IP，保留其封存歷史，來訊另依 CT-01 建立

**CT-08 自動聯絡人不等於手動確認的課堂成員**
- Given 由來訊建立的 source='auto' 聯絡人
- Then 不自動下載附件、不加入課堂檔案同步／備援／存取節點；仍可一對一傳訊與手動下載附件，不建立 Peer 或金鑰信任
- When 只編輯本機備註或 IP
- Then 仍是 auto，不默默取得上述資格；自動來源的名額與內容上限仍生效
- When 使用者在詳情明確選「確認為一般聯絡人」，或明確設為老師並確認
- Then 同交易轉 source='manual'、保留原 id／歷史／草稿並釋出該自動來源名額，可依既有手動名單政策自動下載小附件／加入課堂檔案；仍不等於已驗證身分或取得老師權限（除非另有明確設為老師操作）。確認 UI 與說明由 B1-b 驗證
- And 移除後再次自動恢復先回到 auto／學生，不自動恢復權限；已移除自動來源的名額保持記錄，避免反覆移除繞過上限

## 新增、移除、備註

**CT-10 新增聯絡人一步完成** 【WPF】
- Given 使用者點「＋ 新增對象」
- When 填 IP（必填）與備註（選填）並確認
- Then 名單出現該聯絡人並直接開啟對話；未填備註時顯示 IP；對方離線也可新增

**CT-11 新增重複 IP 時引導到既有聯絡人** 【WPF】
- Given IP `A` 已是聯絡人
- When 再次新增 `A`
- Then 不建新列；顯示「已在名單中」並提供「開啟對話」

**CT-12 聯絡人操作集中在一個選單** 【WPF】
- Given 名單中任一聯絡人（含老師）
- When 右鍵或對話標題的 ⋯
- Then 都看得到：編輯備註、編輯 IP、設為／取消老師、移除聯絡人；兩個入口內容一致

**CT-13 移除聯絡人保留歷史、不是封鎖**
- Given 聯絡人 A
- When 選「移除聯絡人」並在確認視窗看到「只從這台電腦的名單移除，歷史會保留在封存區，不會封鎖對方」後確認
- Then A 從一般清單消失、出現在封存區（唯讀，可查看）；取消則不變
- Then 留在原本的一般聯絡人／未讀篩選（含搜尋條件），不自動跳到封存；對話改選該清單第一位，沒有符合項目則顯示空狀態。狀態列顯示「已移到封存區，可在篩選切換查看」。右鍵、標題 ⋯ 與設定頁的移除入口一致
- Then 使用者切到封存篩選並選取 A 才開啟唯讀歷史；封存／封鎖對話的輸入框不顯示原草稿，改顯示唯讀提示且不能傳送。草稿的本機資料與記憶體緩衝保留，畫面隱藏不能觸發草稿寫入／清除；恢復可編輯聯絡人時才重新顯示保留的草稿
- Then 唯讀時附件、程式碼、貼圖入口都停用並有停用外觀；仍可依既有取消守衛「停止後續重試」，因為這只停止本機舊待送，不是新傳送或收回

**CT-14 編輯備註只影響本機**
- Given 聯絡人 A
- When 編輯備註
- Then 清單、對話標題與通知立即改用新備註；設定視窗明示「只在這台電腦顯示」；對方畫面不變
- Then 無自訂頭貼時以 PeerId／RosterId 優先作為 UTF-8 SHA-256 輸入，取前 4 bytes 的 big-endian 非負整數對既有花色數量取餘數；沒有識別鍵才用原 seed，皆空則用 original。同一鍵在不同程序／電腦結果相同，本機備註與在線狀態不改變已知鍵的花色；自訂設定仍優先，花色清單／順序不變。這不新增身分同步：不同電腦的本機 RosterId 若不同，須待第 2 批共享識別／頭貼同步後才可視為同一鍵

**CT-15 編輯 IP 時歷史跟著聯絡人**
- Given 聯絡人 A 的 IP 由 `x` 改為 `y`
- Then 歷史與草稿留在同一筆聯絡人；`x` 之後若再來訊，依 CT-01 視為新的陌生來訊（現行 CM-10 已知限制）。已排隊的舊 IP 工作不得改送新 IP；晚到舊 ACK 不得確認新對象或復活刪除訊息。只依 accepted socket source IP 歸戶，多網卡不同來源不憑名稱／to_ip／對方聲稱自動合併

## S0 保護界線

- CT-01 同交易涵蓋 classroom 文字與附件 offer；舊 legacy v1 接收亦套用自動加入，但保留其 scope／clear revision guard，且不捏造 stored ACK 或已讀能力。
- CT-02 合併同時更新 v13 ClassroomOutbox.principal，保留 targetIp、messageId、順序、狀態；舊 principal 的草稿／附件 epoch 失效。已讀先於本機 ACK 時回 transient，待確認後再套用，不丟回條。
- CT-13 的 Core 證據是 Removed 封存旗標、唯讀不可送與歷史保留；視窗、確認與封存區入口由 B1-b WPF 驗證。
