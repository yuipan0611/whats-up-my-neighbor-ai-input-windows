# 已讀回條（RR）

決策：D-28（已讀預設開啟，修改 D-10 的預設值；「已送出的回條不可撤回」仍有效）。不改線上協定。

**RR-01 新安裝預設開啟**
- Given 全新安裝
- Then 「傳送已讀回條」為開啟

**RR-02 升級時尊重使用者原本的選擇**
- Given 舊版 enabled=false 且 generation=0（工程上視為從未設定）
- When 升級
- Then 改為開啟，並在設定頁與首次開啟聊天視窗時提示一次「已讀回條現在預設開啟，可在設定關閉」
- Given 舊版 enabled=false 且 generation>0（工程上視為使用者關閉）
- Then 升級後維持關閉；既有 enabled=true 也維持開啟
- And 新版起持久記錄 explicitChoice 與 noticeShown；Core 僅對此次由預設關閉改為開啟的升級提供待提示／確認已顯示 API；新安裝不顯示「升級變更」通知，既有明確選擇不重複提示，WPF 提示另驗
- And 已知限制：舊版點選原本已關閉的選項但 generation 未增加無法識別，依 PM 裁決仍視為從未設定並開啟；不聲稱可還原不存在的使用者操作歷史

**RR-03 對方回線後自動補送**
- Given 回條因對方離線重試超過 8 次而暫停
- When 再次與對方成功通訊（任一 hello／訊息往來成功）
- Then 僅該 socket／已驗證 hello target IP 對象的回條重試額度重新啟動並補送；無效 hello／錯誤回應／其他 IP 不重武裝。回條自己的 hello 不得讓同次失敗無限自我重設，不必重開 App

**RR-04 公平排程**
- Given 前 50 筆待送回條都屬於離線的對象 X
- When 對象 Y 在線
- Then Y 的回條仍會送出，不被 X 卡住；以有界分頁輪轉，不全量載入、不逐筆等待一個對象耗完所有重試

**RR-05 關閉回條時不補送**
- Given 使用者關閉回條
- Then 佇列中尚未送出的回條不再補送；已送出的不撤回；關閉會遞增 generation 並移除佇列，傳送前再檢查 policy generation。停用期間讀過的訊息重新開啟不補排

**RR-06 已讀只在真正看到時送出**（既有行為，回歸保護）
- Then 依 beta.11 的閱讀定位規則：聊天窗在前景且訊息實際呈現才算已讀；背景或停在較早位置不送
