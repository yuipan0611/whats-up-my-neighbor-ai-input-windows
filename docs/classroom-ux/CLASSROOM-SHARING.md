# 課堂檔案共用與完整備援：需求決策

2026-11-05。新增於已核准的 UI-4 老師收件附件索引之後；下列共用與備援**尚未實作於 WPF／網路後端**。

## 使用者已選擇

- 老師維持原本取得教材的方式。同學先拿到教材後，也能明確上傳給全班。
- 老師電腦開著 NekoChat 時作為主要檔案與目錄節點。
- 同學電腦作備援；老師離線時要自動完整接管，**上傳、下載、撤下均繼續**，不能降為僅下載或等待老師回線才接受操作。
- 傳錯可以撤下自己的分享。先採各自管理自己的分享；老師跨使用者管理尚未新增為要求。
- 左側老師下面保留獨立檔案格，改稱課堂檔案，避免暗示只有老師可以分享。

## 產品與資料邊界

- 私人聊天附件不自動公布；分享給全班是獨立、明確的動作。
- 草稿／未完成上傳留在相應操作區，不與老師、同學並列成分類。傳送失敗在對應項目旁。
- 撤下是停止提供這份分享，與清除本機快取分開。不能保證收回別人已下載或另存的副本。
- 正常節點同步撤下紀錄；離線節點重連後同步。斷線分區期間不能聲稱所有離線電腦已即時刪除。
- 沒有任何可用來源時必須明確顯示暫時無法取得，不能把節點接管顯示成檔案已存在。

## 後端必要設計與驗收

這需要新增班級共用目錄與複寫協定，不能把現有單人附件列表或 SQLite／檔案複製當作已完成備援。

1. 每份分享有不重用的識別碼、內容雜湊、分享者操作憑證；不能僅憑 IP／本機老師標籤授予撤下他人分享的能力。不得重新加入數字配對流程；底層憑證方式仍需在實作前固定。
2. 老師與同學節點皆能保存版本化的新增／撤下操作。需要可合併且不復活已撤下項目的目錄；不能用整份舊目錄覆蓋新目錄。
3. 老師離線後由可用備援節點受理三種操作。兩個分區各自接管後重連，必須合併有效分享並保留撤下記錄，不能單靠電腦時鐘決定勝負。
4. 檔案內容仍分塊傳輸、核對大小與 SHA-256。沿用每檔 25 MiB、每台同時兩個傳輸與 512 MiB 管理空間的既有界線；備援副本必須納入空間計算。
5. 顯示實際可用來源及已完成的備援，沒有保存／校驗完成的副本不能計入備援數。不可用來源與需要重新同步的操作須有可恢復狀態。
6. 以至少三個真 TCP＋SQLite 節點驗證主要節點關閉後仍可上傳／下載／撤下；再測節點全部重啟、撤下後舊節點回線、重複操作、斷線、空間不足與越權撤下。
7. 保留舊版一對一文字／附件相容性。共用功能須另作能力宣告，不讓舊版顯示假成功。
8. Windows 實機與不同 DPI、教室網路及多電腦驗收另列，不以 HTML、渲染圖或 CI 替代。

## 畫面狀態

本機互動預覽在 `build/classroom-ui4-preview`：老師主節點／同學接管、上傳、分享者、備援數、撤下確認。目前全部為示範資料與記憶體狀態，無實際上傳或節點接管。新流程先供使用者確認，再轉 WPF 與後端。
