# PR #20：Windows CI 資料庫清理修正

原始失敗：GitHub Actions run `41970051186`，Windows job `127055921790`，來源 `b90a5a1`。一般 Windows、Lite Relay 與 Windows 完整 Core 6433 項通過；Lite Windows 在 `--classroom-all` 的附件 69 項斷言後，刪除 `nekochat.db` 時出現 IOException（檔案被其他程序使用）。本機 macOS baseline 的附件 69 項正常結束，因此不能把本機成功當成 Windows 清理已通過。

`AttachmentChecks.Node.KnownLoopbackFixture` 為修改合成名單 IP 開啟的額外 SqliteConnection 未指定 Pooling，預設使用連線池。Dispose 後底層 handle 可能仍留在池內，Windows 無法刪除資料庫。產品 ChatStore 與其他直接 SQL 測試原本已有 `Pooling=false`；此次讓這個測試連線遵守同一模式，沒有改產品儲存、傳輸、資料庫 schema 或正式 App。

依據：[Microsoft.Data.Sqlite 連線字串與 Pooling 預設](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/connection-strings#pooling)。

保持 `Directory.Delete` 嚴格成功條件，沒有忽略錯誤、加重試或清空全域連線池。附件通過訊息移到清理之後，避免尚未完成清理就印出成功；`--classroom-all` 失敗現在輸出完整 stack trace，讓下一次 CI 保留定位資訊。

驗證命令：`build/classroom-sharing-20261105/run-dotnet.sh run --project windows-lite/NekoChat.Tests -c Release --no-restore -- --attachments`。本機 69 項與 fixture 清理完成、exit 0；原始雲端失敗與本機前後紀錄保存在 `build/actions-fix-20261105`，雲端 Windows 結果以 PR checks 的對應來源 SHA 為準。

變更僅推至既有 `codex/lite-classroom-ux-20261105`，PR #20 保持 Draft，不合併、不執行 Release workflow、不發布或部署；教室雙機與其他 DPI 驗收界線維持。
