# 測試方式與驗證範圍

這份文件說明哪些行為有自動化測試保護、如何執行，以及哪些事情**只能在真實 Windows 上用人工確認**。

對照版本：0.1.0-beta.2。

## 三種測試

| 類型 | 指令 | 會做什麼 | 何時執行 |
|---|---|---|---|
| 離線測試 | `./scripts/build.ps1` | 建置並執行核心、平台與設定測試。不開視窗、不讀金鑰、不錄音、不呼叫 Groq。 | 每次修改後 |
| UI 整合測試 | `Neighbor.Tests.exe --interactive` | 開啟隔離的文字視窗，使用剪貼簿與鍵盤注入，檢查貼上與 UI。 | 發布前與改動貼上、UI 時。會接管桌面，請先安排時段。 |
| 安裝測試 | `./scripts/test-install.ps1` | 安裝、升級、冒煙啟動與解除安裝，核對登錄與檔案雜湊。 | 改動打包或安裝程式時。會寫入目前使用者的登錄與資料夾，最好在測試帳號執行。 |

離線測試與 UI 整合測試的報告分別寫在 `Neighbor.Tests/bin/Release/net48/test-results/offline-tests.txt` 與 `ui-tests.txt`。

## 離線測試保護的內容

| 區域 | 內容 |
|---|---|
| 錄音狀態機 | 開始、完成、取消、重試、錄音保留與期限、設定與目標快照、錄音中斷的通知順序 |
| 錄音格式轉換 | 48 kHz 立體聲浮點與 44.1 kHz 單聲道轉為約一秒的 16 kHz 樣本，1 kHz 測試音的頻率與振幅保持不變，16 kHz 直通長度不變 |
| Groq 請求 | 唯一端點、模型、語言、提示、JSON 回應格式、`temperature` 為 0、WAV 附件；401／403／413／429／5xx、空回應、取消與過大回應 |
| 文字與語言 | 三種輸出模式、法律用語保護、數字轉換、九種語言的文字系統限制、簡繁轉換、emoji 與補充平面字元 |
| 詞典與學習 | 200 詞與 40 字元上限、提示字數上限、啟停與釘選、候選詞的穩定時間與取消、原子保存與損壞資料保留 |
| 快捷鍵與設定 | 快捷鍵註冊與衝突回復、設定保存、預設值（預設不登入啟動、靜音停止關閉）、損壞設定檔保護 |
| Windows 整合 | 認證管理員的新增、讀取、更新與刪除（使用隔離名稱）、登錄與回復、取消先於剪貼簿寫入 |

**離線測試不能證明的事**：真實麥克風的音質與裝置相容性、真實應用程式中的貼上行為、中文輸入法組字、高 DPI 與多螢幕顯示。

## UI 整合測試保護的內容

- 擷取可編輯目標、過期快照阻擋貼上、正確目標收到文字且沒有送出 Enter。
- 焦點切換時阻擋鍵盤注入、密碼欄位拒絕自動貼上、停止觀察後不再允許修字學習。
- 受控測試輸入框中的修字範圍，包含等長、較長與較短替換，以及完整替換本次貼入文字時停止學習。

截圖使用合成資料。100%、150%、200% 的版面是程式化縮放檢查，不代表真實螢幕 DPI 切換已驗收。

## 安裝測試保護的內容

- 基準版（合成的 `0.0.9-ci`，與目前版本使用相同 AppId 與相同 payload）安裝後，登錄的 `DisplayVersion` 與所有 payload 檔案雜湊一致，且沒有登入啟動項目。
- 升級到目前版本後，版本更新、檔案雜湊一致，隔離的設定與詞典檔案雜湊不變。
- 冒煙啟動成功，且仍沒有登入啟動項目。
- 解除安裝後，執行檔與登錄移除，隔離的設定與詞典保留。

**注意**：這是合成前版升級，不是從真實舊版正式版升級，也沒有驗證跨版本資料格式遷移。

## CI

- `.github/workflows/windows.yml`：每次 push 到 `main` 與每個 Pull Request 執行建置、離線測試、UI 整合測試、打包與安裝測試，並上傳 `neighbor-windows-x64` artifact。
- `.github/workflows/release.yml`：推送 `v<VERSION>` 標籤或在 `main` 手動執行時，依序執行相同的步驟，全部通過後才建立預發布版本。細節見 [UPDATES.md](UPDATES.md)。

## 人工驗收清單

以下項目需要真實的 Windows、麥克風與 Groq 帳號，自動化測試不會假裝已驗收。請在正式發布前逐項執行，並把結果寫入 Release 或 Issue。

**可見 HUD 的外部整合驗證（tools/a11y-verification，本輪實測）**

- 工具：`tools/a11y-verification/`（不納入安裝包，不被 `build.ps1` 執行）。宿主程式顯示合成資料的輸入框與 HUD；`verify-a11y.ps1` 從外部程序以 `oleacc` 取得左右眼，使用系統內建的 PowerShell、UIAutomation 與 COM，不安裝任何工具，不錄音，不呼叫 API。
- 結果（實測通過）：MSAA 子元素 2、角色 PushButton、七狀態名稱與啟用狀態；`accDoDefaultAction` 觸發正確事件（Idle 右眼 Start、Recording 左眼 Cancel 與右眼 Finish、RetainedAudio 右眼 Retry）；`Delivering` 與隱藏時沒有事件；移動後視窗到達指定位置，眼睛位置與視窗位移一致；LocationChange 與 NameChange 通知實際送達客戶端（WinEvent hook 計數）；關閉後舊元素不觸發事件，宿主程序結束。
- 焦點：操作前輸入框必須是前景且有焦點（前提）。最終執行中前提成立，兩次眼睛操作前後輸入框皆保持前景與焦點。較早一次量測受操作干擾，結果無效，不計入。
- UIA：**不支援**。橋接沒有暴露任何按鈕元素，也沒有 InvokePattern。`WM_GETOBJECT` 目前只回應 `OBJID_CLIENT`（MSAA），沒有處理 `UiaRootObjectId`。因此 UIA 的 Invoke 目前不能使用，不能當作通過。
- 最終實測（修正審查發現後）：`accState` 的 Unavailable 實際為 `0x1`（`STATE_SYSTEM_UNAVAILABLE`）。事件檢查改為比對事件種類，且只計新增的一筆。LocationChange 與 NameChange 通知的子 ID 為 1 與 2（左右眼），修正前曾送到錯誤的子 ID（2、3），原因是 `AccessibilityNotifyClients` 的參數會被框架重新對應，現改用 `NotifyWinEvent` 直接送出。焦點前提在本次執行成立，且操作前後皆保持。
- 關閉檢查：HUD 視窗確實被銷毀（`IsWindow` 為 false）。關閉後「沒有事件」是弱檢查；釋放後的行為由單元測試保護。
- 仍需人工：Narrator、NVDA 的朗讀；多螢幕與 DPI 下的座標；焦點在其他應用程式搶走前景時的行為。
